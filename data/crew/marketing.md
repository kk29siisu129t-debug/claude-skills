# マーケ（航海士）の蓄積

`agents/marketing.md` の人格が、実行のたびに読み書きする専門知識。
**推測は書かない。** 確定したことと、明示した未確認だけを置く。

## 判定基準（増やしていく）

### 型2: pl軸は3クルーで担当が割れる。同じ事業でも「どこが落ちているか」で担当が違う

metrics.json の pl score は事業ごとに1つしか無いが、実際は マーケ（作る側=リード/CVR/広告/口コミ露出）・
sales（取りに行く側=商談/成約率）・planning（採算=原価/粗利/回収）の3クルーが別角度で埋めている。
score が null でも、他クルーがすでに違う角度で手を付けている場合があるので、着手前に
`data/crew/planning.md` と `data/crew/sales.md` の「指摘の履歴」を必ず確認し、重複しない角度を選ぶこと。
2026-08-27、Tクリニックの pl score null に対し、planning は原価/粗利（回収回数の式）を担当済みだったため、
マーケはファネル側（予約→来院の来院率53%→60-70%の落ち込み区間）を担当した。

### 型3: ToolSearchでMCPツール（会議記録・Googleドライブ）が見つからないことがある

2026-08-27、`ToolSearch` で `SearchMeetings`/`search_files` 等を検索したが `No matching deferred tools found`。
このセッションでは一次データ・会議検索が使えなかった。その場合は既存のローカル蓄積ファイル
（`data/businesses/*.md`、他クルーの `data/crew/*.md`）から測定方法の具体化まで進め、
「一次データは未取得」と明記する。ツールが無いことを理由に何もしないより、測り方の設計は進める。

### 型4: アフィリの「不正の疑い」は症状から手口を逆算する

来院率・来店率が落ちている場合、手口は絞れる。

| 手口 | 来院率は落ちるか |
|---|---|
| リスティング出稿違反（商標買い） | **落ちない**。実在の人が来る |
| クッキースタッフィング（成果の横取り） | **落ちない**。実在の人が来る |
| 架空・低品質の申込 | **落ちる** |

**来院率が落ちているなら、前の2つは症状と合わない。**
商標キーワードで検索して広告が出るかを見れば、1つ目は1分で除外できる（2026-09-11 実施、出なかった）。

**不正か低品質かの区別は、打ち手を選ぶ段階では要らない。**
どちらも「来院しなかった予約を承認しない」で消える。

**承認率を下げたあとに見るのは、成果数ではなく来院数と来院ベースCPA。**
成果数は必ず落ちる。**落ちて正しい。**見る指標を先に決めておかないと、
下がった瞬間に「失敗した」と読んで元に戻すことになる。

下げる前に ASP へ伝えること。承認率はアフィリエイター側の最重要指標で、
黙って下げると優良パートナーまで一斉に離れる。
