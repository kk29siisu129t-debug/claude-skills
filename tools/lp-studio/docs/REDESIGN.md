# v2 改善設計（品質差し戻しへの対応）— 下書き

ユーザーの差し戻し4点（インサイト・日本語・可読性/視認性・FVの動き）への対応を、ここで設計する。
独立したコピー/デザインレビューの確定仕様が届いてから大規模に書き換える。以下はその前の設計と検証計画。

## 1. 失敗の根本原因（v1）

| 症状 | 根本原因 |
|---|---|
| インサイトが無い訴求 | ブリーフが product / audience / problem / promise の**自由文1行ずつ**で、「誰が・どの瞬間に・何で止まるか・本音は何か」を持つ欄が無い。プロンプトも「ブリーフ値は {{key}} で差し込め」と指示しており、インサイトを掘る工程が無い |
| 日本語が変 | 差込トークンを見出しやリードにそのまま入れる設計（`{{audience}}へ。{{product}}`）。長い名詞句が文の部品として不自然に連結される。読み上げ確認の工程が無い |
| FVの反復 | 上部帯（audience）・小見出し（audience+product）・チップ（product）・本文（promise）が同じ内容を4回繰り返す。product に「（オンライン学習伴走・架空）」が入っていて、ブランド名・業態・試作表示が1つの欄に混在 |
| 可読性 | 日本語の文節を考えない改行（「も／う」「決／まっている」）。小見出しが長すぎて主見出しと競合。見出しだけ残るセクション |
| 架空値の誤用 | FVバッジが「4.2 日/週 根拠あり」を成果のように見せる（検証済み根拠だけを出す安全性はあったが、**意味**の検査が無い） |
| 価値の図が無い | 図解がブランド色の無地カード3枚（プレースホルダー）。仕組みを示すデータを持つ欄が無い |
| 動き | FVの全要素が opacity 0 から登場し、見出しが完全に見えるまで PC 1.15秒 / SP 0.79秒、CTA は 1.68秒 / 1.33秒（実測: docs/motion/baseline-v1-timeline.json）。動きが価値の説明に使われていない |

## 2. モデル変更（schema v2、v1 からの移行あり）

### ブリーフ（名前・業態・試作表示を分離）
- `brandName`: 短いブランド名（例: ミチシルベ簿記）。見出しには入れない
- `offerCategory`: 業態（例: 学習計画の伴走サービス）
- `demoStatus`: `fictional-demo` / `prototype` / `live`。ページ上部の細い帯とフッターに**1回だけ**出し、名前や見出しには混ぜない
- `audienceShort`（FVで呼びかける短い呼称）と `audienceDetail`（判定用の詳しい説明）
- `ctaOutcome`: CTAを押すと何が起きるか（例: 日時を選ぶ画面に進みます。面談はオンラインで30分）

### インサイト（仮説として明示）
`insights[]` の各項目:

| 欄 | 中身 |
|---|---|
| `moment` | いつ・どこで（例: 平日の夜、机に座った直後） |
| `struggle` | 何で止まるか |
| `innerVoice` | 本人の言葉（仮説） |
| `currentWorkaround` | 今どうしているか |
| `desiredState` | どうなりたいか |
| `source` | `hypothesis` / `interview` / `survey` / `support-log` |
| `evidenceRef` | `source` が hypothesis 以外のときに必須 |
| `confidence` | 確からしさ |

- `messageAxis`（訴求の軸。例: 勉強前の段取りで止まる夜）と、`primaryInsightId` を持つ。
- **`source: hypothesis` は UI と prompt で常に「仮説」と表示する。** 実インタビューの引用が無い限り、`innerVoice` を「お客様の声」として描画しない。

### 価値の可視化
`valueVisual: { kind: 'task-plan' | 'before-after' | 'timeline' | 'checklist', caption, sampleLabel, items[] }`

- 例: 「学習計画のイメージ」＋「月: 仕訳 例題1〜3（15分）」のような具体的なサンプル。
- `sampleLabel`（「イメージ」「例」）を必須にし、実績のように見せない。
- 画像アップロードは追加しない（HTML/CSSで描く）。

### FVバッジの廃止
- 根拠は根拠セクションで、**文として**出す（数値を先頭に大きく出す「カウンター」は、成果指標でない限り使わない）。
- 根拠に `kind: outcome | policy | process` を持たせ、カウンター表示は `outcome` かつ verified に限定する。

## 3. 生成プロンプト v2（2段階）

1. **インサイトを掘る**
   - ブリーフから「瞬間・障害・本音・今の回避策・望む状態」を3案出す。すべて `hypothesis` とする。
   - 軸を1つ選び、選んだ理由を書く。
2. **コピーを書く**
   - 軸から FV の見出し・リード・CTA周辺の文言を書き、続けて各セクションを書く。
   - 規則:
     - ブリーフ文の書き写しを禁止する（n-gram の重なりを ingest で検査）
     - 見出しにはブランド名・長い名詞句の差込を禁止する
     - FV見出しは声に出して一息で読める長さ（目安22字以内）にする
     - リードは「何をどう助けるか」を1〜2文で書く
     - CTAの直下に `ctaOutcome` を置く
3. **自己点検を JSON に含める**
   - `selfCheck: { readAloud, whatItDoes, ctaOutcome, repeatedPhrases }`
   - ingest で機械検査し、問題があれば警告する。

## 4. レンダラー

- **日本語の改行**:
  - 見出しとリードを `Intl.Segmenter('ja')` で文節に近い単位にまとめ、`<span class="wb">`（inline-block）で包む。
  - CSS は `word-break: keep-all` と `text-wrap: balance`。「も／う」型の分割を起こさない。
  - 手動改行（`\n`）も、PC/SP別に許可する。
- **FV**:
  - 構成は「試作表示の細い帯 → 業態の小見出し（短い）→ 見出し → リード → CTA＋ctaOutcome → 価値の図（学習計画のイメージ）」。
  - 対象者・ブランド名の反復をやめる。
- **価値の図**: 1週間の15分タスクの具体サンプル（UI風カード、「イメージ」ラベル付き）。
- **可読性**: 小見出しの文字を小さくし、見出しとの差を明確にする。本文の行長を40字前後にそろえる。セクション間の余白とリズムを整える。見出しだけのセクションは safe でブロックする。

## 5. 動きの方針と検証計画

| 対象 | 方針 |
|---|---|
| 文字（見出し・リード・CTA） | 最初から表示する（opacity 0 にしない）。わずかな上移動だけ 0.3秒 |
| 価値の図 | タスクが1行ずつ現れて ✓ が付く（0.5〜0.9秒）。**仕組みを見せる動き**で、読み始めを遅らせない |
| 本文 | スクロールで短い reveal（12px・0.5秒）。固定CTAの表示ルールは v1 を維持 |

**計測（docs/record-motion.mjs）**:
- 見出しの完全表示は最初の描画から 200ms 以内、CTA は 400ms 以内
- 図のアニメーションは 1.2秒以内に終わる
- 固定CTAが FV 中・インラインCTAの中央表示中に出ないこと
- reduced-motion では最初のフレームで完成していること
- CLS（レイアウトのずれ）が 0.02 未満であること

**成果物**:
- PC/SP の MP4 と、初回登場の GIF を v1 と並べて比較する。
- 結果は e2e の受け入れ条件にも入れる。

## 6. 2つ以上のブリーフでの確認
- 簿記の学習伴走（既存）に加えて、性質の違う架空ブリーフを1〜2本用意する。候補は「小規模店舗向けの予約受付代行」「子ども向けの週末工作教室の体験会」。
- インサイト・軸・FVコピー・価値の図の種類（task-plan / before-after / timeline）が変わることを、画像と JSON で確認する。
- 生成はどれも、このセッション（Claude Code）が prompt v2 から実際に行う。人手でサンプルを整えて固定することはしない。

## 7. 監査役の品質批評（2026-10-05）で追加した設計

判定は **不合格（売り場として成立していない）**。12件の指摘のうち、上の設計に無かったものを足す。

| 指摘 | 設計 |
|---|---|
| 読者の反論（無料か・何分か・その後いくらか・誰が伴走するか）に答える工程が無い | prompt の1段目で「反論マップ」を作り、各反論を答えるセクションに割り当てる |
| 一番強い本音（試験日から逆算できない不安）を拾わず、FVが「15分」に寄った | インサイト候補を複数出し、選定理由を書かせる。軸と FV の対応を ingest で検査する |
| 創作した悩みが「“」付きの吹き出しでお客様の声に見える | `voiceEvidence` が無い限り吹き出しで描画しない。仮説は「よくある状況（仮説）」として、平叙文のリストで出す |
| 常体と敬体の混在、句点の欠落 | 文体（です・ます）を brief で指定し、ingest で混在と句点を lint する |
| CTA後の事実（費用・所要時間・形式・面談後の案内・伴走者）が無い | `ctaFacts` を必須の欄にし、未確定なら safe export をブロックする。CTA直下に出す |
| 判定できない「向いている人」、本命を突き放す「向いていない人」 | 適合条件は、読者が Yes/No で判定できる条件文にする（prompt の規則と lint） |
| 太字の乱用で主従が無い | 本文400・見出し800の2段にする。h2 は 28〜32px、字数の上限を持つ |
| 除外後の空洞（見出しだけ・中身1件の比較表） | 閾値未満のセクションは safe で丸ごと落とす。必須セクションならブロックする |
| 全セクションが同じ比較カード、同じ余白 | セクションの種類ごとに型を変え、余白のリズムを2〜3段にする |
| ステップに ✓（完了の記号）、巨大な番号が文字に被る | ステップは番号だけにし、文字に被らない位置へ |
| `.js` を body 末尾で付けるため、一瞬表示されて消える明滅が起きうる | `.js` は head の中の小さなスクリプトで付ける（CSP hash 対象）。FVの文字は opacity 0 にしない |
| 固定CTAとインラインCTA（reveal 中で透明）の判定がずれ、CTAが画面に1つも無い瞬間がある | CTA帯は reveal の対象から外す。固定CTAの非表示判定は、インラインCTAが実際に見えてからにする |
| 架空値のカウントアップ演出、等幅でない数字 | カウントアップは廃止する（outcome かつ verified かつ実数のときだけ静的に表示）。数字は tabular-nums |
| アンカー移動・全ページキャプチャ・印刷で reveal 要素が透明のまま残る | `:target` / 印刷 / `beforeprint` で強制表示する。全ページキャプチャは reduced-motion で撮る |

**日本語の改行**: `Intl.Segmenter('ja')` は「終|わら|せ|ない」のように切れるため、そのままでは使えない。次の方式で文節にまとめてから `<span class="wb">` で包む。

- ひらがなだけの断片は前の塊に付ける
- 開きかっこは次の塊に付ける
- 句読点の後で新しい塊を始める

BudouX に近い方式で、外部依存は無い。
