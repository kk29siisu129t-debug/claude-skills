# 監査役（kansayaku）との壁打ち・監査の記録

監査役の役割定義は `agents/kansayaku.md`。独立していて、短く言い切り、根拠が崩れたらすぐ引く。
監査に使った入力は次のものだけです。私的データ・顧客データ・credentials には触れていません。

- 依頼文の仕様と、公開参考の観察仕様
- 添付スクリーンショット
- 今回のコード
- 架空seed

## 1. 設計の壁打ち（実装前）

判定は **条件付き承認** で、指摘は10件と補足2件でした。全件を採用し、対応表は `DESIGN.md` の「v2」節にあります。
主な変更は次の3つです。

- safe export を fail-closed にした（人が承認したセクションだけを公開する）
- 「検証済み」にできるのを人の操作だけにした
- 参考LP固有値の denylist と、LPO の固定判定ルールを置いた

## 2. 実装監査（1回目）

判定は **差し戻し** で、指摘は12件でした。監査役は再現スクリプトで実際にすり抜けを確かめています。全件を修正し、回帰テストは `tests/unit/audit-regressions.test.mjs` にあります。

| # | 指摘 | 修正 |
|---|---|---|
| 1 | ゼロ幅文字・空白・全角で検出器と denylist をすり抜ける | `canon()`（NFKC→書式文字・空白・桁区切りを除去）にかけてから全パターンを照合。入力時にもゼロ幅文字を除去 |
| 2 | 漢数字・架空の推薦文・語彙（タダ・弁護士等）の漏れ | 漢数字＋単位、年代・「〇〇さん（」等の推薦パターン、語彙を追加。ingest でも同じ検出器で拒否（確定ブリーフか verified 根拠にある値だけ通す） |
| 3 | プロジェクト名（`<title>`）を検査していない | safe export で name も検査し、未解決ならブロック |
| 4 | verified 根拠の中身を検査していない | 根拠の主張・出典・単位を検査。推薦は本人同意の出典が必須。単位は allowlist。数値は主張文に含まれること。根拠候補も denylist で拒否 |
| 5 | 部分一致で「91%」が「1%」を裏付ける | 数値トークンの境界で照合。CTA文言は、CTAを置くセクションが参照する根拠だけで照合 |
| 6 | import で verified / approved を無条件に信じる | 生成由来・未来日付・実在しない日付の verified は降格。承認時に内容 hash を保存し、不一致なら承認を外す |
| 7 | 固定CTAの `always` / `after-half` が仕様違反のまま公開できる | `always` は廃止（読込時は spec に置換）。どの案でも FV中・インラインCTA可視中は隠す。safe は spec のみ |
| 8 | コントラスト検査が描画している組合せを覆っていない | 文字用に補正した `--primary-ink` / `--accent-ink` を使い、薄める opacity を除去。検査項目を追加 |
| 9 | LPO の期間の妥当性を検査していない | 実在しない日付は schema エラー。期間の逆転・予定終了日<開始日・28日超は判定しない |
| 10 | 期間をまたいだ比較で「前提を満たす」を出しすぎる | 全案を照合。期間が重複していれば比較しない。長さ・曜日・季節性の未調整は注意として必ず出す |
| 11 | expectedShare の合計が1でなくても黙って正規化する | 全案に指定するか全く指定しないか、合計1を必須に。満たさなければ判定しない |
| 12 | 集計の矛盾（クリック>分母、CV>クリック）を観測として出す | クリック>分母は判定しない。CV>クリックはクリック後CVを出さず、注記する |

## 3. 再検証（2回目）

判定は **条件付き承認** でした。12件のうち10件が閉じ、残りと新規で5件の指摘がありました。全件を修正し、回帰テストを追加しています。

| # | 指摘 | 修正 |
|---|---|---|
| 残1 | 結合文字（下線など）ですり抜ける | `canon()` で `\p{M}` を除去。「参加費ゼロ」「本日23:59まで」も検出 |
| 残2 | バッジの数値が前方一致で通る（120人に12） | 数値の前後両方で境界を見る |
| 残3 | 検証後に根拠の本文を改ざんしても verified のまま | 検証時の内容 hash（`verifiedHash`）を保存し、不一致なら降格 |
| 残4 | 「十分」「一人で」「大学で学んだ」「テレビを見る」を主張と誤検出 | 熟語の除外リストを置いた。大学・テレビは文脈（教員・研究・出演・紹介・掲載）があるときだけ権威として扱う |
| 残5 | 差が観測されたときに検証計画が空になる | 案ごとに再現確認・段階展開の計画（guardrail・停止条件つき）を必ず出す |

## 4. 再検証（3回目）

判定は **条件付き承認** でした。残1〜5は閉じ、新しく3件の指摘がありました。

| # | 指摘 | 修正 |
|---|---|---|
| 新1 | バッジの単位を照合していない（「回答者120人」に 120%） | `metricMatches()` で数値と単位を1組として照合 |
| 新2 | 悪化した案にも「配分を上げる」と提案する。id も重複 | 悪化した案は「悪化の再現確認と配分停止」に切り替え。id は案ごとに一意 |
| 新3 | 「十分」の除外で「たった十分で完了」が素通り | 「十分」は熟語の文脈（な・に・です 等が続く）のときだけ除外 |

## 5. 再検証（4回目）と最終判定

承認条件として1件の指摘がありました。

- **指摘**: 単位が「X/Y」の形のとき、「/Y」側を照合していない（「全4日」に 4日/週）
- **修正**: 数値の直前に「週」「毎週」「1週あたり」等があること、または「値X/Y」の表記を必須にした

**最終判定: 承認。** 監査役は14通りの入力で照合を確認しました。4回の監査で出た指摘（12件・残5件・新3件・条件1件）は、すべて実際に試して閉じています。

テスト件数は unit 69 件、e2e 14 件で、すべて通過しています（実装側で実行）。

## 限界（監査役と合意した前提）

- 主張の検出は語彙・パターンベースで、言い換えを網羅することはできません。そのため主たる防御は「人が承認したセクションだけを公開する」fail-closed です。
- 承認 hash・検証 hash は、承認・検証と内容の **対応づけ** です。改ざんを防ぐ署名ではありません（JSON を書き換えて hash まで計算し直せば通ります）。外部から受け取った JSON は、承認と検証をやり直す運用を前提にしています。
- 監査役の実行権限では `npm test` が拒否されたため、監査役自身はテストを実行していません。代わりに core を直接呼ぶ再現スクリプトで確認しました。テストの実行結果は実装側（このセッション）のものです。
