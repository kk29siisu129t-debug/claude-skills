# Meeting Compass（プロトタイプ）

会議の横に置いて、**「いま何の論点か」「提案・理由・懸念・トレードオフ」「確定した決定と仮案」「未解決」「次に決めること」「アクション」**を構造で見るための画面です。逐語録・話者識別は目的にしていません。

> **正直な前提**：この段階は、架空会議の**台本（fixture）**を順に流すデモと、**キーワード規則**による手入力の簡易分類だけです。AI による理解・音声認識は行っておらず、画面上部に常時そう表示しています。

## 起動

Node.js 20 以上。実行時の依存はありません。

```bash
cd apps/meeting-compass
node server.mjs          # または npm start
# → http://127.0.0.1:5178/ を開く（127.0.0.1 のみで待ち受け）
```

`PORT=xxxx node server.mjs` でポートを変えられます。`file://` で直接開くと ES Modules が読み込めないため、上のサーバーを使ってください。

## 画面構成

スマホ縦持ちを基準にした**縦1カラム**です。デスクトップでも同じ順序で中央に置きます（最大幅は相対単位、固定幅の列なし、横スクロールなし）。

1. デモ操作（再生・一時停止・一歩進める・リセットの細い帯。台本の発言と速さは折り畳み）
2. **いまの論点**（大きな見出し、これまでの論点のチップ、件数の早見ボタン）
3. 議論の構造（提案 → 理由 → 懸念 → トレードオフ → この論点の決定・仮案 → 未分類、すべて縦。空の欄は1行に縮める）
4. 決定と仮案（確定・仮案/再検討・撤回の件数と根拠／撤回理由。撤回済みは折り畳み）
5. 未解決
6. 次に決めること
7. あなたのアクション
8. 手入力
9. 詳細（要確認・論点の履歴・変更履歴・音声〔未接続〕・データ。既定で折り畳み）

E2E は desktop（1440×900）、390×844、360×740 の縦持ちで、上記の順序・同じ左端と幅・左右16px以上の余白・横スクロールなし・長い入力でもはみ出さないことを検証します。
項目の操作ボタンは、マウス環境ではホバー／キーボードフォーカス時に重ねて表示し、タッチ環境では常時表示します。

## 使い方

- **デモ再生**：再生／一時停止（再開）／一歩進める／リセット、速さの切り替え。架空会議は「週次定例の開催形式」→「共有ドライブ整理」→ 脱線（コーヒー）→ 定例に戻る → 仮案の再検討・数字の訂正・撤回 → 明示的合意で確定 → 沈黙だけの「確定」は見送り、という流れです。
- **手入力**：`議題: ○○` で新しい論点。それ以外はキーワード規則で仮分類し、当てはまらなければ「未分類（要確認）」に入ります。種類を自分で選ぶこともできます。
- **編集中の保護**：「修正」を開くとデモ再生を自動で一時停止し、編集を終える（保存・キャンセル・Esc）まで再生と一歩進めるを無効にします。編集フォームは再描画で作り直さないため、入力途中の内容は消えません。
- **修正と確定**：各項目の「修正」で本文・種類・（アクションは）担当／期限を直せます。決定は「確定にする／仮案に戻す／再検討／撤回」。すべて履歴に残ります。
- **論点の履歴**：過去の論点を「表示」で参照（現在の論点とは区別して表示）、「現在の論点にする」で会議の論点を戻せます。
- **データ**：内容はタブのメモリ上だけ。再読み込み・「すべて消去」で破棄。JSON / Markdown の書き出しはボタンを押したときだけ。

## 設計上の約束

| 要件 | 実装 |
|---|---|
| 安定した ID・差分更新 | 全変更はイベント（`web/js/core/model.js` の `applyEvent`）で適用。ID は台本／手入力側が付与し振り直さない。画面はキー付き差分更新（`web/js/ui/dom.js`）で既存ノードを再利用 |
| 重複防止 | 同じイベントID、既存の項目IDへの追加は無視 |
| 訂正・撤回・再検討の保持 | 上書きせず `item.history` と変更履歴に残す。撤回は「撤回済み」として残る |
| 根拠なき合意の禁止 | 確定は `explicit_agreement`（台本で明示）か `user`（画面操作）だけ。沈黙・反対なしは拒否し「合意未確認」と表示。手入力の「決定しました」も仮案 |
| 担当・期限 | 明記されたときだけ設定。それ以外は「不明」 |
| 外部送信なし | CSP `connect-src 'none'`、外部フォント等なし。ESLint で `fetch`/`WebSocket`/`localStorage` 等を禁止 |
| XSS | データは `textContent` のみで描画、`innerHTML` 等は ESLint で禁止、CSP で inline script 不可。Markdown 書き出しは `<` `>` を実体参照化 |
| 音声 | 未接続。マイク・画面許可は要求しない（`Permissions-Policy` でも禁止）。将来案は [docs/audio-path.md](docs/audio-path.md) |

## テスト・検査

```bash
npm install          # 開発用依存（eslint, typescript, @playwright/test）のみ
npm run lint         # ESLint（危険API禁止ルール込み）
npm run typecheck    # tsc --checkJs
npm run test:unit    # node:test
npm run build        # web/ を dist/ に複製し参照切れを検査（バンドル不要）
npm run test:e2e     # Playwright。ブラウザを別途入れる場合は `npx playwright install chromium`
```

Playwright は 1.56.1 に固定。手元の Chromium を使う場合は `PW_CHROMIUM_PATH=/path/to/chromium npm run test:e2e`。
E2E を実行すると `screenshots/` が上書きされます。

## Claude Artifact 版（架空デモのみ）

`npm run bundle:artifact` で `artifact/meeting-compass.html`（単一 HTML の断片）を生成します。掲載先は本人のみ閲覧可能な非公開 Artifact で、共有設定は変更していません（URL はリポジトリに書きません）。

- 中身は `web/js/ui/app.js` から辿れるデモ画面だけ（esbuild で IIFE 1本にまとめ、CSS と一緒にインライン化）。`server/`、ライブ経路、秘密値、実業務データは含めない。
- 外部 CDN・フォント・画像は使わない。出力に通信 API・メディア取得・ブラウザ保存・ダウンロード処理・外部 URL が含まれていたらバンドルを失敗させる。
- Artifact の閲覧画面はページからのダウンロードを止めるため、書き出しボタンは「Artifact版では無効」と表示して押せないようにし、保存処理のコードそのものもバンドルから外す（`scripts/artifact-stubs/download.js` に差し替え）。
- 「AIによる理解・音声認識はしていない」「音声未接続」の表示は通常版と同じ。
- `tests/e2e/artifact.spec.js` は、Artifact の外枠に近い HTML と、Artifact より厳しい CSP の下で、全リクエストを記録・中止して試験する。`MC_ARTIFACT_SERVED=<読み戻した掲載HTML>` を渡すと、実際に配信される HTML（外枠込み）で同じ試験を行う。
- 実際の claude.ai の閲覧画面上での操作確認は、この開発環境からはログインできないため未実施（本人の端末で確認が必要）。

## ライブ経路（未接続）— 実装済みの境界

**実API・実音声では一度も動かしていません（未検証）。** 実接続のアダプタは未実装で、登録済みプロバイダは0件です（`server/live/provider-contract.mjs` の `PROVIDER_REGISTRY` が空）。そのため、どの設定にしてもライブ経路は開始できません。
OpenAI 固有のアダプタは方針変更により実装していません（Circleback 既存利用の調査結果待ち）。公式文書をこの環境から読めなかったため、イベント名やフィールド名を推測した実装も作っていません。

| 実装済み（モックで試験） | 内容 |
|---|---|
| プロバイダ契約 `server/live/provider-contract.mjs` | 文字起こし（final 区間だけを通知）と構造化（JSON を返す）の2つのインターフェース。未設定時は何も送らずに失敗 |
| 設定とゲート `server/live/config.mjs` | 既定は無効。開始には次の4つすべてが必要：①`MC_LIVE_ENABLED=1`、②登録済みプロバイダとその資格情報の**存在**（値は読まない・返さない・ログに出さない）、③会議参加者への告知と外部処理への同意、④開始操作。ループバック以外で待ち受けた場合も無効 |
| 上限 `server/live/budget.mjs` | 金額の概算ではなく、**リクエスト数・セッション時間・音声時間・1回の入力トークン・合計トークン**で強制。送信前に確保し、usage が不明なら最大値で計上 |
| まとめ `server/live/batcher.mjs` | 確定（final）区間だけを最大30秒または1200文字でまとめる。文脈は直近数区間だけ。重複は無視し、停止時に未送信分を破棄 |
| 構造化 `server/live/structuring.mjs` | 追加キー禁止・全項目 required の JSON Schema と独自の厳格検証。未知ID、古い revision、今回の発話に引用が無い確定、ユーザーが最後に変更した項目の上書きを拒否。1件でも不正があれば全体を適用しない。入力は短い現在状態と今回の発話だけ |
| セッション `server/live/live-session.mjs` | ゲート → open → final → まとめ → 構造化（同時1件・タイムアウトで abort）→ 検証 → 差分適用。二重開始の拒否、古い応答は1回だけ再投入、停止で進行中リクエストの abort・接続の close・未送信の破棄。エラー文は長いトークン状の文字列を伏せる |
| 入口チェック `server/live/http-guard.mjs` | Host 許可リスト、Origin 一致、CSRF ヘッダ（定数時間比較）、Sec-Fetch-Site、Content-Type、本文サイズ、トークンバケット。**まだどのエンドポイントにも配線していない** |
| 取得 `web/js/live/capture-session.js` | Meet タブ音声＋マイク／対面マイクの2モード。ゲートが許可しない限り取得関数を呼ばない。画面共有の映像 track は即停止。失敗・共有終了・停止で全 track を停止しリスナーを解除。ブラウザのメディア API を呼ぶ実装は未作成（lint でも禁止のまま） |

- **通信の境界**：`web/` と `server/` のどちらでも `fetch`・`WebSocket`・ネットワーク系モジュールの import を ESLint で禁止しています。今回、例外は1つも追加していません。
- **テスト時の遮断**：テストは `tests/unit/no-network.mjs` の下で実行します。fetch・WebSocket・ループバック以外へのソケット・TLS・DNS をすべて遮断し、各テストファイルの最後で試みが0件であることを確認します。

### 実接続までに本人が必要な手順（未実施）

1. 使うサービスを決めて承認する（Circleback の調査結果次第）。外部接続・秘密値・課金の承認も必要。
2. 公式仕様（認証、イベントやフィールド、データ保持、料金）を確認する。
3. アダプタを別ファイルで実装し、`PROVIDER_REGISTRY` に登録する。実接続アダプタは、承認後に ESLint の通信禁止ルールで例外ファイルとして明示する（共通基盤の禁止はそのまま）。
4. HTTP エンドポイントと UI（同意チェック、録音中表示、停止）を配線する。CSP の `connect-src` と `Permissions-Policy` は、有効時だけ `self` に緩める。
5. サーバーを起動するプロセスの環境変数として設定する：`MC_LIVE_ENABLED=1`、`MC_LIVE_PROVIDER=<名前>`、資格情報（ブラウザ・localStorage・Git・ログには置かない。`.env` をコミットしない）。
6. `127.0.0.1` で起動し、画面で同意して開始する。

`store:false` のような送信オプションを使っても、それは「提供側に保存させない指定」であり、提供側の保持がゼロであることを意味しません。保持条件は提供側の規約で確認が必要です。

## 制限（まだできないこと）

- 実会議への参加、音声取得、文字起こし、AI による構造化は**できません**（デモ台本とキーワード規則のみ）。ライブ経路は共通基盤とモックテストまでで、実接続アダプタ・HTTP エンドポイント・UI 配線は未実装です。
- キーワード規則は語の有無だけを見ます。否定文・皮肉・文脈は理解しません（例：「心配はない」も懸念に入る）。必ず人が確認・修正する前提です。
- 保存はメモリのみで、複数人での共有・同期はありません。
- 元に戻す（undo）はありません。訂正・撤回は履歴に残ります。
