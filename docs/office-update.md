田原さんの8事業ダッシュボードを最新化する。定期タスク3本（平日7:00・10:45・16:00／土日7:00）から
このファイルを読んで実行する。**手順を変えるときはここだけ直す。**

- 公開先 Artifact: `https://claude.ai/code/artifact/f7b26faa-d5ec-4822-bc4d-c69eff4f548a`
- 実体: `C:\Users\kk29s\claude-hub`（必ず cd してから作業する）
- ビルド: `python scripts/build-office.py` → `office.html` を生成
- **HTMLは絶対に手で書かない。** データを直してビルダーで作り直す

## モード

呼び出し側から `朝の回` か `日中の回` が渡される。

| | 朝の回（7:00・土日） | 日中の回（10:45・16:00） |
|---|---|---|
| 会議の取得範囲 | 前日〜今日 | 今日 |
| 残タスクの取り直し | する | しない |
| 監査 | する | しない |

## 0. この2つは必ず守る（初回の実行で両方破られた）

**A. 走ったら必ず `data/crew/runs.jsonl` に1行残す。** 差分なしで終わるときも、
詰まって止まるときも、例外なく1行。ログが無い＝走っていない、と判断できる状態にする。

**B. `python scripts/build-office.py` を実行していない回は、絶対に publish しない。**
ビルドしていない `office.html` を publish すると、画面で保存されたチェックを古い状態で
上書きする危険がある。**「読む→publish」だけで終わる経路は存在しない。**
publish する回は必ず `更新→ビルド→publish` の3つが揃う。

```
差分なし  → 読まない・ビルドしない・publishしない・ログだけ書く
差分あり  → 読む → データ更新 → ビルド → publish → ログを書く
```

## 1. 新しい会議を取る（まずこれだけ）

ToolSearch で先に読み込む：
`select:mcp__9c71711c-00eb-4a9e-925b-31936e852b5c__SearchMeetings,mcp__9c71711c-00eb-4a9e-925b-31936e852b5c__SearchActionItems`

SearchMeetings を上記の範囲で呼ぶ。`data/issues.json` の `asOf` と各 issue の `basis` の日付を見て、
**まだ反映していない会議だけ**を対象にする。

**新しい会議が1件も無ければ、ここで打ち切る。**
Artifact を読むな。ビルドするな。publish するな（読むだけで1回30kトークン使う）。
`data/crew/runs.jsonl` へ次の1行だけ追記して、それで終わり：

```json
{"at":"<ISO時刻>","crew":"system","biz":"全社","state":"done","task":"定期更新（差分なし）","note":"新しい会議なし。読み込み・ビルド・公開はしていない"}
```

代表の席に未処理の指示が入っているかもしれないが、**会議が無い回にそれを見に行かなくてよい。**
指示は次に会議があった回か、朝の回で拾えば足りる。空振りの回に30kを払わない。

## 2. 画面の状態を取り込む（更新するときだけ）

Artifact ツールの `action:"read"` で上記URLを読む。保存されたHTMLから
`<script id="state" type="application/json">` を取り出し、次の3つをローカルに反映する。
**これを飛ばすと、田原さんが画面でつけたチェックが消える。**

- `queue` … 代表の席に入った未処理の指示。**あれば最優先で対応する**（内容次第では手順3〜4より先）。
  対応したら `data/crew/queue-done.json` に `"<at>|<text>"` を追記
- `mtDone` … 済にした残タスク → `data/mytasks-done.json` に上書き（配列）
- `mtNot` … 「自分のじゃない」指定 → `data/mytasks-notmine.json` に統合（キー→理由の辞書。既存の理由は消さない）

## 3. 経営課題を更新（`data/issues.json`）

新しい会議の notes から、数字が動いた課題を更新し、新しい課題を足す。
**Python スクリプトでタイトル一致でパッチする**（ファイル全体を読み込んで context を食わない）。

- `sev` は達成率から `(100-達成率)/100`。出せないものは根拠を `cause` に書く
- `basis` には**会議名と日付（JST）**を必ず書く
- **`meeting.createdAt` は UTC。** 日本の朝の会議は前日の22〜23時台で返るので、必ず JST に直してから日付にする。
  2026-09-08 にこれで31件ずれた
- 解決した課題は消す
- **定義が違う数字を並べて「悪化」と書かない**（例：Meta単体CPA ¥87,000 と 全体クロスCPA ¥71,000）
- 終わったら `asOf` を今日の日付に

## 4. 業績トレンドを更新（`data/trend.json`）

天気の根拠。**課題の量ではなく「業績が伸びているか」**で決める。
新しい売上・件数が出ていたら `prev` / `now` / `watch` / `basis` を書き換える。

- `wx`: `fine`(伸びている／未始動) `partly`(兆しはあるが未達) `cloud`(足踏み) `rain`(落ちている)
  `storm`(大きく落ちている) `fog`(測れていない)
- **`by:"代表指定"` が付いているものは勝手に変えない**（POTEX・EXTAGE・Tクリニック・origin）。
  数字が明確にずれたら `watch` にだけ書き、天気は据え置く
- `dormant` 付き（失業保険・MUSE・補助金コンサル・AI company）は未始動なので `fine` のまま
- **数字が取れていない事業を晴れにしない。** `fog` にする

## 5. 残タスクを取り直す（朝の回だけ）

`SearchActionItems` を `status="PENDING"`、`pageIndex` 0 から。既定で本人分のみ返る。

- 会議日（JST換算）が**直近15日以内**のものだけ採用。それより古いものは Circleback 側で完了マークが
  運用されておらず7月分まで残っているので使わない
- 事業の判定は会議名から。`data/mytasks.json` の既存 `m` フィールドが対応表
- `d`（発生日）と `due`（期限）は**JSTに直して**入れる。`due` は description の文中にしかない

### 精査（ここが要）

残すのは次の3つだけ。

1. 田原さん本人が**出席・訪問・面談する約束**
2. 本人の人脈／**本人しか話せない相手**への連絡（オーナー・先生・候補者・紹介元）
3. **本人が決める・本人が書く**と議事録に明記されているもの

制作・配信設定・シート更新・事務連絡・チーム内実務は、名前が出ていなくても本人ではない。
**迷ったら外す。** 混ざったままだと一覧そのものが読まれなくなる。

外したものは `data/mytasks-notmine.json` に理由付きで入れる（理由は画面の行に出るので本人が戻せる）：
「代表が手を動かすものではないと判断（制作・設定・シート更新・事務連絡・チーム内実務）。違っていれば画面で戻せます」

POTEXは 2026-09-08 に **39件中36件が本人以外**と判定された。実務は福井Ryusuke・加藤M.・有田Megumi・
宮田S.・新川篤史が回している。**厳しめに外す。**

`data/mytasks-notmine.json` と `data/mytasks-done.json` に既にあるものは触らない。

## 7. 稼働ログ（差分なしでも必ず書く）

`data/crew/runs.jsonl` に1行追記：

```json
{"at":"<ISO時刻>","crew":"system","biz":"<主に更新した事業>","state":"done","task":"定期更新","note":"<何を変えたか1〜2行>"}
```

## 8. 監査（朝の回だけ）

`kansayaku` サブエージェントを**1つだけ**立て、その日更新した issue の `basis`（会議名・日付）が
Circleback の実際の会議と一致するか、数字の取り違え・基準の混在が無いかを検品させる。
指摘が出たら直してから再公開する。

**サブエージェントは使用量を食う（1回で週次枠の10%になった実績あり）。日中の回では立てない。**

## 守ること

- 破壊的な操作をしない。`data/*.json` は変更前に `.bak-<日付>` を取る
- 出典が無い数字は書かない。断定できないことは断定しない
- **対外に出るものは作らない**（メール・DM・投稿）。この更新は画面の中だけ
- 田原さんへの通知はしない。変更内容は画面の「稼働ログ」に出る
- 詰まったら `runs.jsonl` に `"state":"blocked"` で理由を残して終わる。**同じ方法で再試行しない**
