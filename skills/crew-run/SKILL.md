# 乗組員を起こす

6部署の人格を起こし、**各自が自分でタスクを決めて**動かす。指示は出さない。
出すのは「起きろ」だけで、何をやるかは各部署の自走ルールが決める。

## 部署と軸

| 軸 | 部署 | slug | 船での役 |
|---|---|---|---|
| 全般 | No.2（秘書） | `chief-of-staff` | 賄い方 |
| 売上利益 | 営業 | `sales` | 突撃隊長 |
| 売上利益 | マーケ | `marketing` | 航海士 |
| 売上利益 | 経営企画（財務） | `planning` | 会計長 |
| 顧客満足度 | プロダクト | `product` | 船医 |
| 採用数 | 人事部 | `hr` | 船員長 |
| **独立** | **監査役** | `kansayaku` | 見張り番 |
| **別枠** | **品質審査** | `reviewer` | 検品 |

## 監査役と品質審査は別扱い（2026-08-27）

**この2つは「3部署」の枠に数えない。**

- **`reviewer`** — 各部署が `content/` か `reports/` にファイルを書いたら、
  **その部署自身が起動する。** オーケストレータが起こすのではない
- **`kansayaku`** — 数字を含むもの・対外に出るものを代表に上げる前に起動する。
  **No.2 の下ではなく独立している。** 監査役の判定を No.2 の意向で曲げさせない

## 誰を起こすか（毎回ここを判断する）

**6部署を毎回起こさない。** 1部署あたり15万トークン前後かかる。全員なら1回で90万を超える。

### 必ず起こす

- **No.2（秘書）** — 全般の持ち場。滞留の仕分けは毎回価値がある

### 条件付きで起こす

上から順に見て、当てはまる部署を**最大2つ**まで足す。合計3部署が既定。

1. **`runs.jsonl` に `running` のまま24時間以上残っている部署** — 停滞。最優先で起こす
2. **`blocked` を書いたまま戻っていない部署**
3. **蓄積ファイルの「指摘の履歴」に、結果が空欄の行がある部署** — 宿題が残っている
4. **直近2日の会議で、その部署の軸の数字が動いた** — 営業なら商談・成約、マーケならCPA・CVR、
   経営企画なら売上・原価、プロダクトなら返金・口コミ、人事なら面談・採用
5. **7日以上起きていない部署** — 順番に回す

### 冷却期間（2026-08-27 追加）

**直近24時間以内に稼働した部署は、条件1（停滞）と条件2（詰まり）以外では選ばない。**

これを入れないと、条件3（未確認の行がある）が効きすぎる。蓄積が増えるほど未確認行は増えるので、
**同じ部署ばかり選ばれ続け、一度も起きない部署が出る。** 実際そうなりかけた。

秘書の「必ず起こす」も、定期実行に限る。手動で連続実行するときは冷却期間を優先する。

### 起こさない

上のどれにも当てはまらない部署は起こさない。**空回りは何もしないより悪い。**

ユーザーが「全員」と明示したときだけ6部署すべてを起こす。その場合は**起こす前に
使用量が3倍になることを一文で伝えて、同意を取る。**

## 手順

### 0. 代表の席の指示キューを読む

バーチャルオフィスの Artifact を `action: "read"` で読み、`<script id="state">` の
`queue` 配列を見る。**未処理の指示があれば、それを最優先で扱う。**

- 指示は No.2（秘書）が読んで、**どの部署の持ち場かを判断して振り分ける**
- 振り分けた指示は、処理後に `queue` から外して Artifact を再公開する
  （`build-office.py` を実行し直せば空の queue で再生成される）
- **代表が明示的に出した指示は、自走ルールより優先する。** 自走は指示が無いときの動き方

### 1. 状態を読む

```
data/crew/runs.jsonl     稼働記録
data/crew/*.md           各部署の蓄積（指摘の履歴で結果が空欄の行を探す）
data/metrics.json        3軸の測定状況
```

### 2. 起こす部署を決める

上の判断基準で選ぶ。**選んだ理由を1行ずつ書いて、ユーザーに見せてから起こす。**
誰を起こしたか分からないまま動くのが一番まずい。

### 3. 並列で起こす

選んだ部署を**同じメッセージで並列に**起動する。順番に起こすと待ち時間が積み上がる。

各部署への指示は**「自走ルールに従って、自分でタスクを決めて実行しろ」だけ**でよい。
タスクの中身をこちらで決めない。決めた瞬間に自走ではなくなる。

渡すのはこの3点だけ:

- 人格定義のパス `claude-hub/agents/<slug>.md` を読むこと
- 蓄積ファイルのパス `claude-hub/data/crew/<slug>.md` を読むこと
- 終わったら `runs.jsonl` と蓄積ファイルを必ず更新すること

> 補足 — `~/.claude/agents` はセッション開始時に読み込まれる。繋いだ直後のセッションでは
> `subagent_type` に slug を渡せないことがある。その場合は汎用エージェントに
> 人格定義のパスを渡して「まずこれを読め」と指示する。

### 4. 戻ってきたら突き合わせる

各部署の報告を鵜呑みにしない。**`runs.jsonl` と蓄積ファイルが実際に更新されているかを確認する。**
報告だけして記録を書いていない部署があれば、それを指摘する。

部署どうしの指摘が矛盾していたら、**両方をユーザーに見せる。** どちらかに寄せない。

### 5. ダッシュボードを作り直して保存する

```
python scripts/build-dashboard.py
```

そのあと Artifact として再公開する（同じURLに上書き。デスクトップのアイコンがそこを指している）。
最後に `scripts/hub.ps1 save` で GitHub に反映。

## 報告のしかた

長い報告書にしない。この4つだけ。

1. **誰を起こしたか、なぜか** — 1行ずつ
2. **各部署が自分で選んだタスクと、その結果** — 1〜2行ずつ
3. **`skipped` を書いた部署** — 該当なしで終わったならそう言う。隠さない
4. **代表にやってほしいこと** — **必ず最後に、独立した見出しで置く**

   - 件数を先に書く（「3件です」）
   - 1件ずつ、**誰に・何を・いつまでに**を書く。「確認が必要」で終わらせない
   - 期限のあるものを上に
   - ゼロなら「**今回あなたの手は不要です**」と明記する。省略しない

   長い報告の中に埋もれると、読んだのに動けないまま終わる。

## 2026-08-26 に変わったこと（各部署へ必ず伝える）

1. **ドライブの数値シートを直接読んでよい。** 議事録だけで止まらない。
   出典（シート名・タブ名・取得日）を必ず書かせる
2. **社内ファイルの更新まで可。** ただし**他人所有のファイルは読むだけ**。
   削除と共有設定の変更は不可。上書き前に元の値を残す
3. **送信は引き続き不可。** 下書きまで
4. **失業保険とエクソソームは「伸ばす対象」。** 畳む判断はしない。まず実数を取りに行かせる
5. **成果物はファイルに書き出させる。** 分析だけで終わらせない。
   `content/drafts/` に依頼文や指示書、`reports/` に分析。書いたら reviewer を起動させる
6. **数字が無くても止まらせない。** 未確認の数字は使わない構成に書き直して完成させる。
   「まず確認が必要です」で止めるのは禁止。確認するための依頼文まで書かせる
7. **8事業すべてで田原さんに決裁権がある。** 打ち手は「提案する」ではなく「決める／指示する」で書かせる。
   選択肢を並べさせない。推奨を1つ出させる。
   ただし**本人に上げるのは本人しか決められないものだけ**にし、他は任せ先を名指しさせる

## 会議記録の取り込み（常設）

**各部署に毎回、前回稼働以降の会議記録を読ませる。** セットアップ時の一度きりにしない。
代表と経営陣が口頭で出した決定・方針変更・制約を拾わないと、蓄積が古い前提で固まる。

**発言記録（transcript）を読ませる。要約ではない。** 発言者を区別させる。
代表の発言と他の経営陣の発言と外部の人の発言は重みが違う。

## 代表へのフィードバック

**監査役だけが持つ機能。** No.2 には持たせない。部下の立場では甘くなるため。

代表本人から依頼された機能なので、定期実行のたびに監査役が判断して出す。
出すものが無ければ出さない。**お世辞は書かせない。**

## 守ること

- **タスクを代わりに決めない。** 自走ルールに任せる。こちらで決めると学習が進まない
- **起こしすぎない。** 既定は3部署。全員は月次の棚卸しのときだけ
- **記録が無い稼働は稼働ではない。** `running` と `done` が両方書かれて初めて完了
- **矛盾を丸めない。** 部署どうしが違うことを言ったら、そのまま出す
- 外向きの操作（メール送信、ファイル公開、社外への連絡）は、どの部署にもやらせない
