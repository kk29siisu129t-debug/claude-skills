# 経営日次ブリーフ

ユーザーは8事業を並走する経営者。**時間がない。** 情報を集めることではなく、
**今日どこに手を打つか**を決め、**手を動かせるものは代わりに終わらせる**のがこのスキルの仕事。

## ユーザー自身が会議で言っている基準（最優先で守る）

Circleback の議事録から採取した、本人の言葉。ここを外すと本人が嫌う形式になる。

> 数字の報告って、特に数字を共有してほしいわけではなくて、そこから導出される課題と解決策につなげたいんで
> 　— グロース_朝会

**数字を並べるだけの報告は失格。** 必ず「数字 → 導出される課題 → 解決策」の3点セットで書く。
数字だけの行、課題だけの行は書かない。

> 昔は3時間以内って言ってたんですけど、僕の部署だけ絶対1時間以内。
> 分解しないと抽象度高いまま入れちゃうんで、結局時間かかる
> 　— グロース朝礼

**打ち手はすべて1時間以内の単位に分解する。**「検証する」「整理する」で止めない。
何分、誰が、何をするかまで割る。合計時間も出す。

> 逆算しないと、刺さるものも刺さんない
> 　— 全社マーケMTG

**目標から逆算した数字を出す。** 「−250万」で止めず、単価で割って必要件数と日次ペースまで出す。
その上で、届かないなら「届かない」と書く。

> 誰の解像度も高くなくて怖い。本当にこの人たちは正しい情報言ってるんだろうか
> 　— meet - Vizz ビジネス

**数字の出所と確度を明示する。** 報告値どうしが矛盾していたら、必ず指摘する。
月次と累計の混在、報告達成率と実算の不一致は実際に起きている。黙って使わない。

> クイックダーティーっていう言葉を流行らせましょう
> 　— EXTAGE 福田卓馬さんとの1on1

**完璧を待たない。** 直すほうが速い状態で出す。「作りましょうか」と聞かない。

> 相手の売上・利益を上げる文脈で話す
> 　— 経営朝礼 8/26（森田さんへのFB）

社外向けの提案を書くときは、自社の提供内容ではなく**相手の利益額**で書く。

## 手順

### 1. 材料を取る（並列で投げる）

- `SearchMeetings` — 直近2日。事業名ではなく**日付で引く**。会議名で絞ると取りこぼす
- `SearchActionItems` — `status: PENDING`。担当はユーザー本人
- カレンダー — 今日と明日の予定。締切と衝突していないか見るため

数値がドライブにしかない事業は、必要なときだけスプレッドシートを読む。毎日は読まない。

### 2. 事業ごとに「数字 → 課題 → 解決策」を出す

**この3列を必ず揃える。** 数字だけの行は書かない。本人が明確に嫌う形式。

| 数字 | 導出される課題 | 解決策 |
|---|---|---|
| 完走者CV率32.4% / 未再生9.1% | 最大レバーは特定済み。なのに今日の施策は「再生前」のCTA差し替えで、完走率に効かない | 離脱地点を1本確認し、直前をカット。刷新を待たない |

各数字に**確度**を付ける。「確度高／中／低」＋低い理由。
報告値どうしが矛盾していたら、そこを課題として上げる。数値がない事業は「記録なし」と書き、
**空白は停止と同じものとして扱う。** 推測で埋めない。

逆算も入れる。「−740万」で止めず、単価で割って必要件数・日次ペースまで出す。

### 3. 課題を絞る

全部は挙げない。**その日に手を打つ意味があるものだけ。** 目安3〜5件。

優先順位のつけかた:

| 優先 | 種類 | 見分け方 |
|---|---|---|
| 最優先 | **ユーザー待ちで他人が止まっている** | 誰かが「◯◯さんの情報待ち」と言っている |
| 高 | **期限が今週内** | 締切・イベント日が7日以内 |
| 高 | **打ち手が判明済みなのに未着手** | 会議で原因特定まで済んでいるのに動いていない |
| 中 | 数値のビハインド | 目標未達だが原因未特定 |
| 低 | 恒常的な弱み | 口コミ数、体制、士気など |

**最優先は特に見落とすな。** 経営者が握ったまま止めている案件は、その人が動くだけで複数人が動き出す。
費用対効果が桁違いに高い。

### 4. 打ち手を1時間以内に分解する

課題1つにつき、打ち手は1つに絞る。選択肢を並べない。決めるのが仕事を増やす。

そのうえで**必ず1時間以内の単位に割る。** これは本人の管理ルール。

```
15分  エクソソームの名義を確定する
  10分  番美さんに連絡し、個人／法人どちらが有利か確認
   5分  大森さんに名義を伝える  ← これで書類作成が動き出す
```

各ステップに、あなた（ユーザー）の実作業時間と、他人に投げる分を分けて書く。
合計時間を必ず出す。合計が3時間を超えたら、打ち手を減らす。

会議で既に方針が出ているものは、**それを繰り返さない。**「で、止まっている理由は何か」を書く。

### 5. 実行する

課題を「私が終わらせるもの」と「あなたにしかできないもの」に分ける。

**私が終わらせられるもの**（勝手にやってよい）
- 資料・提案書・台本・訴求文・記事の作成と修正
- 数値の集計、スプレッドシートの整形
- 施策の設計（ファネル、価格、フロー、AIの仕組み）
- 議事録からの整理・優先順位付け

**あなたにしかできないもの**（一覧にして渡す。私はやらない）
- 人への連絡（LINE・電話・メール送信）
- 契約・株式・金額の意思決定
- 社外への提案の最終判断

**確認を取ってからやるもの**
- メールの送信、Notion/ドライブの既存ファイルの書き換え、外部への公開

やると決めたものは**その場で終わらせる。** 「作りましょうか」と聞かない。作って見せる。

### 6. 出す

Artifact で1枚にまとめる。ターミナルに長文を流さない。読み返せる形にする。

構成（この順を守る）:
1. **いま誰が動いているか** — 稼働ボード。人を図として出す（下記）
2. **今日の3つ、逆算で** — 目標から逆算した数字つき
3. **あなたが渡せば動くもの** — 誰に何を渡せば動くか
4. **数字から導出した課題と解決策** — 3列。確度つき
5. **今日の打ち手、1時間以内に分解** — 分単位
6. **作っておいたもの** — 実物
7. **あなたにしかできないもの** — 連絡と意思決定だけ

### フロア図の作り方

**人ではなく機能（部署）で描く。** 個人が忙しいかどうかより、機能が埋まっているかどうかが判断材料。

会社のフロア図を真上から見た SVG を描く。

- **実線の部屋** = 動いている機能。担当と定例会議の両方がある。中に在席の点を打つ
- **細い実線 ＋「兼務」** = 担当はいるが専任でない、または1人抜けると止まる
- **点線の部屋 ＋「空席」** = 担当も定例もない

そのうえで**書類を運ぶ人を歩かせる。** CSS `offset-path: path('...')` に
`offset-rotate: 0deg`（人型は回転させない）、脚は `rotate` のキーフレームで振る。

動線はこう組む:

```
営業部 → 空席の部屋の前で停止（数秒） → 引き返す → 廊下 → 社長室
```

**これが図の主張。** 持っていく先が空席だから、書類が全部社長室に戻る。
社長室に「N件 滞留」と出す。図の下に、どの部署からどの空席へ何を運んでいるかを文章で併記する
（動く文字は読めないため）。

`prefers-reduced-motion` では歩行を止め、`offset-distance` を空席の扉の位置で固定する。

### 空席の裏取り

「空席」と書く前に必ず議事録を検索して確認する。推測で空席と書かない。

| 機能 | 検索語 | 空席の判定 |
|---|---|---|
| 監査・内部統制 | `決裁` `監査` | ヒット0、または規程の資料はあるが運用の言及がない |
| 秘書・経営補佐 | `秘書` | ヒットが候補者の前職の話だけ |
| 法務 | `契約書` | 都度、外部か担当者任せ。締結漏れの記録がある |
| 財務 | `資金繰り` `PL` | 本人が「これから勉強する」段階 |

**空席は抽象論なので、必ず実害とセットで出す。** 議事録から症状を引いて並べる
（未運用の決裁規程、見積もりなしの請求、報告値の不一致、入金漏れ、契約締結漏れなど）。
出典の会議名と日付を必ず添える。

スキルの稼働状況も同じ場所に小さく出す。

## 書き方

- 数字は必ず入れる。「好調」「課題」だけの行は消す
- 事業名を主語にする。「売上が」ではなく「POTEXの8月売上が」
- 会議記録の要約をそのまま貼らない。**差分と示唆だけ**書く
- 前日と変わっていない項目は「変化なし」と1行で済ませる。同じ説明を毎日書かない

## 注意すべき制約

- **失業保険**: 申請書類の代行はできない。制度説明と手続き案内まで。この線を越える提案をしない
- **エクソソーム**: 化粧品として「吸収される」と断言不可。ミネラル結合型を強調した訴求も避ける
- 医療・法務・税務の判断が必要なものは、打ち手ではなく「誰に確認するか」を書く
