議事録の型

書けない人は、喋れない。議事録を、漏らさず・階層化して・15分以内に出せる状態まで持っていくための実施キット。

対象 リーダー陣 所要 20分×4回（一括90分も可） 事前課題 9/24(木)に配る 合格 10点中8点

この研修のゴールは、受講者が翌朝の会議で書いた議事録が、その日のうちに8点以上を取ること。理解ではなく、翌日の成果物で測る。

実施は 9/28(月)〜10/1(木) の朝会に20分×4回で刻むのを推奨（9/25に90分の空きが無いため。08章に理由と一括90分版の両方）。

01

直すもの、直さないもの

マネージャーレベルでも議事録が書けていない。議事録でこれなら、日々のコミュニケーション全体で実行力が落ちている可能性が高い。だからこれは文書作法の研修ではなく、処理能力とロジカルの研修として設計する。

欠陥 → 基準
いま起きていること欠けている力当日つける基準
重要事項を漏らす 処理能力 網羅／決定・数字・懸念・引き受けが1つも落ちていない
階層化できない ロジカル 構造／すべての行が、会議の大目的から下ろした木の枝になっている
アクションが直後に送られてこない 期日と責任 速度／終了15分以内に、誰が・何を・いつまでに（時刻）が出ている

なぜ議事録からやるのか

そもそも書けない人たちが喋れるわけがない。それを一発で喋ろうとするので、曖昧な部分が出る。

田原／【定例】リーダーMTG 2026-09-17

報告が曖昧なのは、話し方の問題ではなく、書けていないことの症状として扱う。書けるようになる順序でしか、喋れるようにはならない。だから報告研修・提案書研修より先に、ここをやる（2026-09-20 広告自動化MTGでの合意）。

これは2026-07-14に決まっていたこと

同日の経営朝礼で、「議事録を書かせることで処理能力・ロジカル思考の向上も狙う」と方針が決まっている。あわせて、ファシリと議事録担当を別の人間に分けること、持ち回りにすること、会議後すぐに全員へ送ることも同じ場で決まった。今回はそれを運用に落とす回であって、新しい方針を出す回ではない。冒頭でそう言うと、受講者側の「また新しいことが増えた」が消える。

当日扱わないもの

  • 議事録ツールの選定（Notion / スプレッドシート / マインドマップ）。ツールの話に逃げさせない。いま使っているもので書く
  • ファシリテーション技術そのもの（別研修）
  • 会議体の要・不要の議論（会議体の棚卸は別の場）
マインドマップについて、先に線を引いておく

「マインドマップでいいですか」は必ず出る。答えは決まっている。思考の整理には優秀だが、議事録には使わない。理由は2つ。論理分解が苦手な人が使うと階層がずれる。そして一覧性が乏しく、後から入った人が読めない。（田原／有田1on1）

02

型 — 7つのブロック

この順番で書く。順番を入れ替えない。空でも見出しは残す（空であること自体が情報になる）。

  1. ミッション・ビジョン会議の頭で読み合わせる。議事録の1行目にも置く。目的から下ろすための起点で、飾りではない。
  2. この会議の大目的「売上利益の最大化」「顧客満足度の最大化」「優秀な人材の採用数の最大化」のどれか1つ。組織エンゲージメントを扱う会議ならそれを足す。言葉も統一する。「売上アップ」と書かない。
  3. 前回ネクストアクションの確認1件ずつ ✅／❌。❌ は理由と、いつまでに出し直すかをその場で書く。ここを飛ばすと、決めたことが毎週消える。
  4. KGI数字。〈値・時点・分母・出典〉をセットで書く。目標との差と達成率まで。丸めない。49.3%なら49.3%と書く。
  5. KPIKGIを分解した枝。各枝に〈現状 → 課題 → 打ち手〉の3点を必ず付ける。打ち手には担当1人と期限（時刻）を付ける。
  6. ネクストアクション会議全体から拾い直して、1か所にまとめる。誰が・何を・いつまでに。KPIの中に書いたものも、ここに再掲する。読む人はここしか見ない前提で書く。
  7. この会議で扱わないもの出たが本会議の大目的に属さない論点を、送り先と日時つきで書く。「→ 1M会議にて実施」「→ 金子さん」。これを書かないと、会議が毎回伸びる。

03

階層化の4ルール

「ロジカルに」では直らない。判定できる手順に落とす。

  1. 1つ下は、必ず1つ上を達成するための部品にする「売上」の下に置けるのは「予約数」「単価」「成約率」。「採用」は入らない — それは別の木。
  2. 同じ階層に、違う種類のものを混ぜない数字と感想、結果と打ち手を横に並べない。「実績200万」と「頑張ります」が同じ深さにあるのが典型的な不合格。
  3. 3階層で止める4階層目が必要になったら、それは別会議の議題。その場で第5ブロック（扱わないもの）へ送る。
  4. 語尾を揃える体言止めなら全部体言止め。「〜した」「〜が必要」「〜だと思う」が混ざると、決定と感想の区別がつかなくなる。読む人は決定だけを探している。

その場でできる判定：下から上に読む

書き終えたら、末端から上に向かって「これをやれば、1つ上が達成される」と声に出して読む。言えなければ階層がずれている。

書き手の上級技

発言をそのまま写すだけなら誰でもできる。「なぜこの人はいま、この場面でこれを言ったのか」を横に一言足す。それをやると、メモを取っている人がその会議で誰よりも考えていることになる。（田原／リーダーMTG）

04

落ちやすい12項目

「重要事項を漏らす」は記憶力の問題ではなく、見に行く場所を知らない問題。会議の終了2分前に、このリストを上から当てる。

  1. 数字の分母と時点「31.4%」だけでは再現できない。何分の何を、いつ時点で見たか。
  2. 目標との差実績だけ書いて、ギャップを書かない議事録が多い。差額と残り営業日まで。
  3. 未達の理由が、特定か推測か「たぶんLPが悪い」と「計測の結果LPのCVRが0.26%」は別物。どちらかを明記する。
  4. 決めなかったこと／保留にしたこと決まったことより忘れられる。保留なら、いつ決めるかまで。
  5. 反対意見と、出した人合意に丸めない。反対があったこと自体が、次に効く情報。
  6. 誰かが口頭で引き受けたこと「じゃあ僕やっときます」は本人がいちばん忘れる。その場で第4ブロックへ。
  7. 期日を時刻まで「本日中」ではなく「16:50まで」。「来週」ではなく「9/29(月)12:00」。
  8. 社外に投げるものは、誰が連絡するか担当が社内で止まると、期日だけが過ぎる。
  9. 数字の出典どのシートの、どの列か。次の人が同じ数字を出せる状態にする。
  10. 次回までに変わる前提キャンペーン終了、人員の増減、季節変動。書いておかないと来週の議論が壊れる。
  11. その場で決められなかった理由情報がないのか、決裁者がいないのか。前者なら誰が取りに行くか、後者なら誰をいつ押さえるか。
  12. 扱わないと決めたものと、送り先送り先が空欄なら、それは「扱わない」ではなく「落とした」。

「問題ないです」が出たら、この4つで返す

曖昧報告をその場で止めるための定型。書き手にも同じ4つを持たせる — 書けない行は、聞いて埋める。

  1. どの数字が、いつ時点で、いくらですか（上流から順に）
  2. 目標に対して何%ですか
  3. 足りない分は、何を、いつまでにやると埋まりますか
  4. それは誰の担当ですか

「問題ないです」自体は禁止しない。なぜ問題ないのかを基準で言えれば合格。基準（この進み方なら／この達成率なら／この行動をしていれば）を先にリーダーが持つ。

06

会議中と会議後の運用ルール

会議中

  1. 議事録は1人担当にしない喋っている人以外が書く。発言者が交代したら書き手も交代する。全員が、いやでも内容を理解しなければいけない状態を作る。
  2. 画面共有するのは議事録そのもの資料ではなく議事録を映す。議論になったら、資料の該当箇所に飛ぶのではなく議事録のカーソルをそこへ移す。書いている内容と全員の認識が合っているかが、その場で見える。
  3. その場で階層に入れる後で整えるのは禁止。後で整えると、整える時間そのものが発生し、漏れも増える。第2ブロックの雛形を開いた状態で会議を始める。
  4. 終了2分前に第4・第5ブロックを読み上げるネクストアクションと、扱わないものを声に出す。誰が何をいつまでにが決まるまで会議を終わらせない。

会議後

  1. 社内は終了15分以内にスレッド投稿3人で書いた場合は、終了後に突き合わせてから15分以内。完成度より速度を優先する。
  2. クライアントは30分以内、できれば直後対面なら終わってすぐ送る。言った言わないの余地を残さない。
  3. 期限は時刻で切る「本日中」「来週」は差し戻し。「16:50まで」「9/29(月)12:00」。
  4. 次の回は、前回の議事録を複製して数字を空欄にして始めるゼロから書かない。構造は固定、数字だけ入れ替える。1回書けば、以降は更新するだけになる。
社内に締切が2つあるので、この研修で1本に揃える

2026-07-14 の経営朝礼では「会議後30分以内にSlackで全員にメンションして送る」と決まり、同日のグロース朝礼では澄川さんが「終了15分以内にスレッドへ」と指示している。会議体ごとに別の数字が生きている状態。

9/25以降は、社内は15分・クライアントは30分（できれば直後）に統一する。厳しい方に揃える理由は、速度が落ちて困ることはあっても、速すぎて困ることがないため。

Tクリニック経営会議で実際にやっていること

前週の議事録をそのまま複製し、数値を 【※】 に置き換えて会議に持ち込んでいる。構造・KPIツリー・対策の見出しは前週のまま。会議は 【※】 を埋める作業になる。これが「毎回ゼロから書く」を無くす唯一の方法。

0点をつけるときの伝え方

語尾を丸めない。「ここは良いけど、ここがダメ」と言うと良い方だけが受け取られる。「0点です。何が言いたいか分かりません」と点数で言い切る。ただし感情と論理は切り分け、トーンは明るく保つ。強いことを言っても反感を買わない出し方をする。

この強度はリーダー・マネージャー以上に対してのみ。メンバーレベルには使わない。

分割版は合計80分。弱いのは、全員が同じ場で同時に基準を揃える効果。

付A

社内にある良い議事録

当日、実物を画面に映す。3本とも社内のもので、この型はここから抜き出した。

1 ／ Tクリニック 経営会議（週次）

  • Vision・Mission → 会議大目的（売上利益／顧客満足度／人材の3本）→ KGI → KPI → 対策、と4階層で一貫して下りている
  • 大目的のうち本会議で扱わないものに「→ 1M会議にて実施」「→ 金子さん」と送り先が明記されている
  • 拠点別の表に〈目標・修正目標・着地予想・実績・着地進捗・単価目標〉が並び、分母と定義が揃っている
  • 翌週分は数値を 【※】 にした複製。構造は固定、数字だけ入れ替える運用の実例
  • 過去分（時系列の課題と、解決済みの印）を末尾に残している。経緯が消えない

当日の使い方：「これを1回作れば、以降は 【※】 を埋めるだけになる」と言って見せる。

2 ／ EXTAGE 経営朝会

  • Mission・Vision の直下に「会議の大目的」が4つ並び、本会議で扱うのは1つ目だけと分かるようになっている。2つ目（顧客満足度）と3つ目（採用）には「→ 別会議にて実施」、4つ目（組織エンゲージメント）には「→ 総会会議を組織課題定例とマージ」と、残り3つすべてに行き先が書いてある
  • 「前回NAの確認」が独立ブロックとして最初に置かれている
  • KPI が担当者名つきで分解されている（リード数 → 紹介／直営業／自社マーケ／DM営業、それぞれに担当）
  • 体制変更の議題が〈目的 → 手段 → いつ〉で書かれ、日付が入っている

3 ／ Tクリニック 組織定例

  • 定性の会議でも構造化できる実例。〈今週のGood → アラートと対策 → 組織を良くするために必要なこと → ネクストアクション〉
  • 「アラートの定義」が議事録内に書いてある（パフォーマンス低下／工数圧迫／退職可能性／雰囲気）。定義を先に置くと、拾うべきものが揃う
  • 各項目に「例」と「実例」が分けて書かれ、書き手が何を書けばいいか迷わない

4 ／ passlabo 会議体の棚卸

  • LINE登録 → フォーム申込 → 審査合格 → 日程確定 → 着座 → 契約、とファネルが1本の数列になっている。どこで何人落ちたかが一目で分かる
  • 落ちた箇所に「施策：〜」がその場で付いている（13名離脱 → 施策：ツール使用）
  • 契約理由と失注理由が両方書かれている。失注理由を書く議事録は少ない
付B

発言の原文

この型の根拠。当日スライドに1枚だけ混ぜるなら、最初の1本を使う。いずれも会議記録からの引用。読みやすさのため、語順の整理と、音声書き起こしの明らかな誤変換（例：「授業」→「事業」）の訂正のみ行った。趣旨と主張は変えていない。

そもそも書けない人たちが喋れるわけがない。それを一発で喋ろうとするので、曖昧な部分が出る。だから議事録文化を作りたい。事前に準備してもらって、それを報告する形のほうがいい。

本当の本当は、この場で議事録を取っていきたい。リアルタイムで、話したことをバーッと階層化してもらって、漏れがないか。会議は後から入ってくる人もいるし、書いている人の認識が合っているかも見たい。
